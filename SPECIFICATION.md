# Marketplace Module — Project Specification

## Context

Generic multi-marketplace platform for digital goods. Supports multiple independent marketplaces on one server. Sellers submit products, marketplace admins approve/reject them. Licenses are generated internally when an external payment module confirms a purchase. This module does NOT handle payments.

## Core Concepts

| Concept | Description |
|---------|-------------|
| **Marketplace** | Independent storefront (e.g. "Code Pet Store", "Theme Store"). Own catalog, sellers, admins. Multiple on one server. |
| **Seller** | Submits products to a marketplace. Can be in multiple marketplaces. |
| **Admin** | Manages a marketplace: approves/rejects products, manages sellers. Multiple admins per marketplace. |
| **Product** | A digital good. Submitted by seller, reviewed by admin. Lifecycle: draft → pending → approved/rejected → published. |
| **Asset** | Files belonging to a product (images, sounds, manifests, previews). |
| **License** | Generated by this module. Ties a product to a machine/user. Created when external payment module confirms purchase. |

## Flow

```
Seller submits product → Admin reviews → Approves → Published in catalog
Payment module confirms purchase → POST /api/v1/licenses/create → License key generated
Client app activates license → POST /api/v1/licenses/activate → Binds to machine
Client app downloads assets → GET /api/v1/assets/{productId}/{file} → License-authenticated
```

## Architecture: Hexagonal (Ports & Adapters)

### Rules

1. **`core/` is framework-free** — domain models, validators, ports, exceptions. NO Spring annotations.
2. **`application/` layer** — DTOs (records), Commands (records), Services (@Transactional orchestration), Mappers (custom, NO MapStruct)
3. **`infrastructure/` layer** — inbound adapters (REST controllers, event listeners), outbound adapters (JPA persistence, file storage)
4. **External modules import ONLY from** `application/` (services, DTOs) and `core/` (ports, exceptions)
5. **Lombok rules:**
   - Domain models: `@Builder @AllArgsConstructor @NoArgsConstructor @Data`
   - JPA entities: `@NoArgsConstructor @Data` only (NO @Builder)
   - Services: `@Slf4j @Service @RequiredArgsConstructor`
6. **JPA entity annotation order:** `@NoArgsConstructor` → `@Data` → `@Table` → `@Entity`
7. **Sequence-based IDs:** `@SequenceGenerator` with `allocationSize=50`
8. **DTOs as Java records** with validation annotations
9. **Error handling:** `MarketplaceException(errorCode, params, message)` + `@ControllerAdvice`
10. **Testing:** Integration tests with Testcontainers PostgreSQL, `BaseIntegrationTest` base class, `{Entity}Inventory` test data factories, GIVEN-WHEN-THEN structure

### When Adding Features (8-Step Process)

1. Define domain model in `core/model/`
2. Create port interface in `core/port/` (for external dependencies)
3. Add DTOs/commands in `application/dto/`
4. Add application service in `application/service/` for orchestration
5. Implement inbound adapter in `infrastructure/inbound/`
6. Implement outbound adapter in `infrastructure/outbound/`
7. Register beans in `config/`
8. Keep `core/` framework-free

## API Specification

### Public API (auth: `X-Api-Key` header -> resolves marketplace)

**GET /api/v1/marketplaces/{slug}/catalog** -- Browse published products
```json
// Response 200
{
  "marketplace": { "name": "Code Pet Store", "slug": "code-pet" },
  "products": [
    { "id": 1, "name": "Dragon", "description": "A fiery coding dragon",
      "tier": "premium", "priceCents": 199, "previewUrl": "/api/v1/assets/1/preview.gif",
      "sellerName": "mradovic" }
  ]
}
```

**POST /api/v1/licenses/create** -- Called by payment module after purchase
```json
// Request (auth: internal service API key)
{ "productId": 1, "maxActivations": 3 }
// Response 201
{ "licenseKey": "A1B2-C3D4-E5F6-G7H8", "productId": 1, "maxActivations": 3 }
```

**POST /api/v1/licenses/activate** -- Called by client app
```json
// Request
{ "licenseKey": "A1B2-C3D4-E5F6-G7H8", "machineId": "sha256-of-machine" }
// Response 200
{ "success": true, "ownedProductIds": [1] }
// Response 400
{ "success": false, "error": "Maximum activations reached (3/3)" }
```

**POST /api/v1/licenses/validate** -- Periodic revalidation by client app
```json
// Request
{ "licenseKey": "A1B2-C3D4-E5F6-G7H8", "machineId": "sha256-of-machine" }
// Response 200
{ "valid": true, "ownedProductIds": [1, 3] }
```

**GET /api/v1/assets/{productId}/{filename}** -- Download product asset (auth: `X-License-Key` header)
```
Response 200: binary file content (obfuscated on disk, served as-is)
Response 403: license doesn't own this product
```

### Seller API (auth: `X-Seller-Key` -> resolves seller)

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | /api/v1/sellers/products | Submit product to marketplace (multipart: JSON + files) |
| GET | /api/v1/sellers/products | List own products across marketplaces (with status) |
| PUT | /api/v1/sellers/products/{id} | Update a draft or rejected product |

### Admin API (auth: `Bearer JWT` -> resolves admin + marketplace scope)

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | /admin/api/marketplaces | List managed marketplaces |
| POST | /admin/api/marketplaces | Create marketplace |
| GET | /admin/api/marketplaces/{id}/products | List products (filter by status) |
| PUT | /admin/api/products/{id}/review | Approve or reject a submitted product |
| PUT | /admin/api/products/{id}/publish | Publish an approved product |
| PUT | /admin/api/products/{id}/unpublish | Unpublish a product |
| GET | /admin/api/marketplaces/{id}/sellers | List sellers in marketplace |
| POST | /admin/api/marketplaces/{id}/sellers/invite | Invite seller by email |
| PUT | /admin/api/sellers/{id}/suspend | Suspend or unsuspend a seller |
| GET | /admin/api/marketplaces/{id}/licenses | Browse/search licenses |

| GET | /admin/api/marketplaces/{id}/stats | Dashboard stats |

## Product Lifecycle

```
DRAFT -> (seller submits) -> PENDING -> (admin reviews) -> APPROVED or REJECTED
APPROVED -> (admin publishes) -> PUBLISHED
PUBLISHED -> (admin unpublishes) -> APPROVED
REJECTED -> (seller edits & resubmits) -> PENDING
```

## License Key Generation

Format: `XXXX-XXXX-XXXX-XXXX` (16 uppercase alphanumeric chars). Uses `SecureRandom`. DB unique constraint with retry on collision.

## Security

```
/api/v1/marketplaces/*/catalog  -> ClientApiKeyFilter (X-Api-Key)
/api/v1/licenses/create         -> Internal service API key
/api/v1/licenses/activate       -> ClientApiKeyFilter (X-Api-Key)
/api/v1/licenses/validate       -> ClientApiKeyFilter (X-Api-Key)
/api/v1/assets/**               -> ClientApiKeyFilter + LicenseKeyFilter (X-License-Key)
/api/v1/sellers/**              -> SellerApiKeyFilter (X-Seller-Key)
/admin/api/**                   -> AdminAuthFilter (Bearer JWT)
/admin/**                       -> AdminAuthFilter (Thymeleaf pages)
/health                         -> permitAll
```

## Asset Storage

- Path: `${storage.path}/marketplaces/{slug}/products/{productId}/{filename}`
- On upload: XOR-encrypt with key derived from `SHA-256(obfuscationSecret + productId)`
- Manifests and previews stored unencrypted; binary assets (sprites, sounds, images) encrypted
- `obfuscationSecret` from env var `OBFUSCATION_SECRET`

## Architecture Rules

- `core/` contains **domain models, validators, ports, and exceptions** (framework-free)
- `core/port/` contains **outbound port interfaces** (implemented by infra)
- `core/exception/` contains **module exceptions**
- `application/dto/` contains **shared DTOs, enums, and commands**
- `application/service/` handles orchestration (@Transactional allowed)
- `application/mapper/` handles conversions between Commands, Domain models, and DTOs

## No Code Generation Libraries

**DO NOT use code generation libraries** such as:
- MapStruct (for mappers)
- Lombok's `@Builder` on entities (use on domain models is OK)
- Any annotation processor that generates code at compile time

Write **custom mapper classes** with explicit mapping logic instead.

## When Adding Features

1. Define domain model in `core/model/`
2. Create port interface in `core/port/` (if external dependency needed)
3. Add DTOs/commands in `application/dto/`
4. Add application service in `application/service/` for orchestration
5. Implement inbound adapter in `infrastructure/inbound/`
6. Implement outbound adapter in `infrastructure/outbound/`
7. Register beans in `config/`
8. Keep `core/` framework-free at all times
