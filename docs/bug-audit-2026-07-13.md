# Bug Audit — 2026-07-13

## Scope

A code review of the code-pet project hunting for potential bugs and misbehaviors across three areas:

1. **Hooks + event pipeline** — `hooks/scripts/*.js`, `src/app/event-server.js`, `src/app/state-machine/*.js`
2. **Electron app core + renderer** — `src/app/*.js` (main, process/window/pet management, settings, terminal-focus), `src/renderer/*.js`
3. **Marketplace / licensing + usage tracking** — `src/app/http-client.js`, `marketplace-*.js`, `license-*.js`, `premium-store.js`, `src/tracking/**`

## Method

Three parallel review sweeps produced ~30 candidate findings. The highest-severity items were then hand-verified against the source line by line.

Each finding is tagged:

- **Confirmed** — the file:line and behavior were re-read and verified directly against the source.
- **Plausible** — reported by a review sweep, consistent with the surrounding code, but not independently re-verified line by line.

No code was changed. These are findings only; fixes are follow-up work (each should get its own issue per the project's issue-first policy).

## High severity

### 1. Path traversal via manifest filenames — *Confirmed*

`src/app/premium-store.js:50-52, 55-58, 63-67`

`_downloadRemote` writes each asset with `fs.writeFileSync(path.join(destDir, filename), data)`, where `filename` comes straight from the downloaded `manifest.json` — `sprite.file`, `manifest.icon`, and each value in `manifest.sounds`. None are sanitized. `path.join(destDir, "../../../.zshrc")` escapes `destDir`, and `path.join` returns an absolute path unchanged.

**Failure scenario:** a compromised or MITM'd marketplace serves a manifest with `sprites: {a: {file: "../../../.zshrc"}}`. On download, code-pet overwrites an arbitrary file outside the pet directory with attacker-controlled bytes. `marketplace-api.downloadAsset` only `encodeURIComponent`s the filename for the request URL — that does not protect the filesystem write.

### 2. Partial download bricks a pet permanently — *Confirmed*

`src/app/premium-store.js:44-53, 74-76`

`manifest.json` is written to disk *first* (line 45), then sprites are fetched in a loop. If any sprite fetch throws, the error propagates and the already-written `manifest.json` is never cleaned up. `isDownloaded(petId)` returns true whenever `manifest.json` exists (line 75), and both the startup recovery loop (`src/app/main.js`) and the activation flow (`src/app/window-manager.js`) do `if (isDownloaded(petId)) continue;`.

**Failure scenario:** the network drops after the manifest is written but before all sprites arrive. `download()` rejects, leaving a manifest with missing/partial sprites. On every subsequent launch the pet is treated as already-downloaded and is never repaired — it renders with missing sprites forever.

**Related:** the manifest is written *before* `JSON.parse(manifestBuf)` runs (lines 45 → 47). A non-JSON response (an HTML error page, a truncated body) is persisted to disk, then the parse throws — same permanent lockout via `isDownloaded()`.

### 3. Session-end safety net can kill the shared app for all other sessions — *Confirmed* — **Fixed**

`hooks/scripts/on-session-end.js:36-41` (with `send-event.js` timeout = 1000ms)

When `sendEvent('falling_asleep')` returns `false`, the hook calls `pm.stopApp()`, which quits the entire single-instance Electron process. But `false` means "unreachable **or** the request timed out" — not only "server is dead."

**Failure scenario:** several concurrent Claude Code sessions share one pet app. One session ends while the server is alive but busy and takes >1000ms to answer. `sendEvent` resolves `false`, `stopApp()` POSTs `/shutdown` (which succeeds, since the server is actually up), and `app.quit()` tears down every other session's pet. A single ending session wipes out everyone's pets on transient slowness.

**Fixed:** the hook now runs a second confirmation probe (`pm.healthCheck()`) before the teardown and only calls `stopApp()` when the server is genuinely unreachable — a healthy-but-slow server is left alone. Covered by a new integration test in `test/integration/hook-session-end.test.js`.

## Medium severity

### 4. Unguarded `killProcess` can hang startup forever — *Confirmed*

`src/app/event-server.js:202-203` + `src/app/process-manager.js:52`

In the `server.on('error', ...)` handler for `EADDRINUSE`, the code does `const pid = readPid(); if (pid) killProcess(pid);` with no try/catch. On non-Windows, `killProcess` calls `process.kill(pid, 'SIGTERM')`, which throws `ESRCH` when the PID is dead or reused. The throw happens inside the async error listener, so neither `resolve` nor `reject` of the `startServer()` promise is ever called — `await startServer()` in `main.js` never settles and the overlay is never created.

**Failure scenario:** a previous instance crashed leaving a stale `app.pid` pointing at a now-dead PID, and port 31425 is held by something else. `EADDRINUSE` + dead PID → the app hangs silently on launch. Note that `stopApp` wraps the identical `process.kill` call in try/catch — this omission is inconsistent.

### 5. AppleScript injection via unescaped `tty` — *Confirmed*

`src/app/terminal-focus.js:47, 63`

`focusByTty` interpolates `ttyPath` directly into the AppleScript source (`if tty of t is "${ttyPath}"`). Every other string put into AppleScript (`appName`, `projectPath`, `projectDirName`) goes through `escapeAppleScriptString`; `ttyPath` does not. `ttyPath` originates from the HTTP `/event` body field `body.tty` → `pet.updateProcessInfo(body.claudePid, body.tty)` (`event-server.js:155`) with no validation.

**Failure scenario:** a crafted POST to `127.0.0.1:31425/event` with a `tty` value containing `"` plus AppleScript, followed by a focus-terminal trigger, executes arbitrary AppleScript. Local-only (the server binds 127.0.0.1) and requires the terminal app to be Terminal/iTerm, but it is a real injection path from an unauthenticated local endpoint.

### 6. Revoked/refunded pets never lose access — *Confirmed*

`src/app/license-manager.js:92-102, 116-121`

Both `activate()` and `validate()` union the server's `ownedPets` into the existing local set (`existing.add(...)`) and never remove entries the server dropped. `isOwned()` reads the stored list.

**Failure scenario:** a pet is refunded or revoked server-side. The next `validate()` returns the reduced list, but the local set still contains the revoked petId, so `isOwned(petId)` stays true indefinitely — a revoked license effectively never loses access.

### 7. Renderer removal race drops a live pet — *Confirmed*

`src/renderer/pet-manager.js:23-33, 82-91`

`removePet` calls `stateMachine.destroy()`, adds `.removing`, and schedules `slot.remove()` + `this.pets.delete(project)` 300ms later. If a new event for the same `project` arrives inside that window, `updatePet` finds `pets.has(project)` still true, reuses the destroyed entry, and calls `setState` on a destroyed `Pet`. Then the pending timeout fires and removes the slot + map entry anyway.

**Failure scenario:** a session is removed (dismiss, or work_finished → remove) and a fresh event arrives <300ms later. The pet is silently dropped from the overlay while its session is live. The removal timeout should verify the entry is still the same (still marked `.removing`) before deleting.

### 8. Session killed mid-work leaves an orphaned "working" pet — *Plausible*

`hooks/scripts/on-session-end.js:36` + `src/app/state-machine/base-state.js` / `idle-state.js`

`falling_asleep` only removes the project when the pet is in `idle`; `working`, `planning`, and `waiting_for_action` ignore it (via `BaseState`'s default). If a real termination happens without a preceding `Stop` (no `work_finished`), the pet is stuck non-idle.

**Failure scenario:** the user kills or closes Claude while it is actively working (no `Stop` fires) → `SessionEnd` with `reason: other` → `falling_asleep` → ignored in `working`. The pet stays "working" forever, the registry never empties, so the 5s idle-shutdown never triggers, and with `CODE_PET_IDLE_CLEANUP` off by default the project is never reaped.

**Note:** CLAUDE.md frames only-idle-removal as intentional, but the orphan-on-hard-kill consequence looks unintended. Flag for a maintainer decision rather than an obvious fix.

### 9. Credential headers forwarded cross-origin on redirect — *Plausible*

`src/app/http-client.js:43-54`

On 301/302/303/307/308 the original `headers` object is passed unchanged to the recursive `request()` for the new URL, with no same-origin check. `downloadAsset` sends `X-License-Key` and the bearer helper sends `Authorization: Bearer …`.

**Failure scenario:** the marketplace responds `302 Location: https://some-cdn.example.com/asset` (typical S3/CDN offload). The license key or JWT is then sent to a different host. Standard hardening (drop auth headers when the redirect origin differs) is missing.

### 10. Activation "succeeds" with zero pets when catalog fetch fails — *Plausible*

`src/app/marketplace-api.js:31-48, 65-89`

`activate()`/`validate()` call `getCatalog()` first, but `getCatalog()` swallows any error and returns `[]`, leaving `_productToPet` empty. `_resolveProductIds` then maps every owned productId to `undefined` and filters them out → `ownedPets: []`. Also `success: result.success !== false` treats an empty `{}` 200 body as success.

**Failure scenario:** a user activates a valid key while the `/products` call transiently fails. `activate` returns `success:true, ownedPets:[]`, `license-manager` saves the key and stamps `validatedAt`, and the UI shows a successful activation with no pets. The merge-only `validate()` (see finding 6) never repairs it.

## Low severity

Unless marked *Confirmed*, these are *Plausible*.

### 11. Sticky `permissionMode` misroutes state restores — *Confirmed*

`src/app/event-server.js:156`. `permissionMode` is set only when truthy and never cleared, unlike `lastAgentId` which is reset to `null` on every event (line 157). A stale `'plan'` can linger across turns, so a later `action_completed` restores the pet to `planning` instead of `working`.

### 12. Invalid event still creates a pet and resizes the overlay — *Confirmed*

`src/app/event-server.js:154-160`. `registry.getOrCreate()` and the `resizeForPetCount` side effect run before `pet.handleEvent` validates the event name. A garbage POST (`{"event":"garbage","project":"/x"}`, or a body with no `event`) mints a phantom idle pet and grows the overlay before returning.

### 13. EADDRINUSE persistent error handler never removed — *Confirmed*

`src/app/event-server.js:193-214`. The retry path adds a `server.once('error', ...)`, but the original `server.on('error', ...)` stays bound. On a retry failure both fire (redundant kill + re-scheduled retry), and the persistent handler also survives past a successful start, so any later runtime server error re-enters the port-conflict/kill logic.

### 14. No response-body size limit in the HTTP client

`src/app/http-client.js`. `request()` accumulates all chunks with no cap, for text and binary alike. The `timeout` only covers socket inactivity, not total bytes, so a steady stream is never cut off — a malicious or misbehaving server can drive unbounded memory growth (OOM) in the Electron main process during asset download.

### 15. `before-quit` does not await the usage flush

`src/app/main.js:149-160`. Electron does not await async `before-quit` listeners, so the process can exit before `await usageStore.flush()` resolves. Pending single-flight writes can be lost. The docs (`docs/usage-tracking.md`) claim the flush drains pending writes before exit, which overstates the guarantee — blocking quit would require `event.preventDefault()` + a later quit.

### 16. productId ↔ petId mapping is fragile to renames and collisions

`src/app/marketplace-api.js:163-166`. `petId` is derived purely from the product display name (`name.toLowerCase().replace(/\s+/g, '-')`) yet is used as the stable identity in `license.json` and as the recovery lookup key. A server-side rename orphans the owned pet (recovery logs "no productId … skipping" and never re-downloads); two names differing only by case/punctuation collide and overwrite each other in the map.

### 17. Non-atomic settings write can reset all settings

`src/app/settings-store.js:51`. `save()` does a direct `fs.writeFileSync`. A crash mid-write leaves truncated JSON; on next launch `load()` catches the parse error and silently resets to defaults, losing the license key, per-project pet choices, and buyer email. A temp-file + `rename` would make it atomic.

### 18. Pets beyond `MAX_VISIBLE_PETS` (8) are clipped, not handled

`src/app/window-manager.js:367` vs `src/renderer/pet-manager.js:35`. `resizeForPetCount` caps window height at 8 slots, but the renderer keeps appending `.pet-slot` elements with no cap. With 9+ concurrent sessions the extra pets render outside the overlay bounds — invisible and unreachable, with no indication.

### 19. Ring-buffer eviction is a no-op for tiny `maxEvents`

`src/tracking/usage-tracker.js:22-25`. `drop = Math.floor(maxEvents * 0.25)`; for any `maxEvents < 4`, `drop === 0`, so eviction removes nothing while `length > maxEvents` stays true, and the in-memory buffer grows unbounded. The default (2000) is unaffected — only a misconfigured tiny `maxEvents` triggers it.

### 20. `MARKETPLACE_ID=0` / NaN silently falls back to the default

`src/app/marketplace-config.js:36-53`. `getMarketplaceId()` returns `config.marketplaceId || DEFAULT_MARKETPLACE_ID`, so a configured `0` falls back to the default, and `Number()` of an invalid value yields `NaN` that flows through unguarded in the constructor. (Env > file > default precedence itself is correct.)

### 21. Miscellaneous smaller items

- **1MB body cap can drop large `action_completed` events** — `src/app/event-server.js:49` vs `hooks/scripts/on-post-tool-use.js`: the hook forwards the full `tool_input` object unbounded; a big `Write`/`MultiEdit` payload can exceed 1MB → 413 → the pet fails to restore state.
- **413 response never reaches the client** — `src/app/event-server.js:52-56`: `req.destroy()` runs before the outer catch tries to `sendJson(res, 413, ...)`; writing to the destroyed socket fails silently.
- **`shutdownTimer` not nulled when it fires non-empty** — `src/app/event-server.js:34-43`: latent; if the timeout ever runs while `registry.size > 0`, the stale non-null timer blocks all future idle-shutdown scheduling. Not currently reachable, but the defensive `size === 0` check implies the authors anticipated it.
- **`getJson`/`postJson` mutate the caller's headers + unguarded `JSON.parse`** — `src/app/http-client.js:84-85, 96-97`: `headers['Accept'] = …` mutates the passed-in object; a 200 with a non-JSON body throws a raw `SyntaxError` out of the client.
- **CSS selector injection from unsanitized manifest ids** — `src/renderer/pet-styles.js:19-27`: `petType` (manifest `id`) and sprite-key `state` are interpolated into selectors, `@keyframes` names, and `animation` shorthand without sanitization; a malformed id (spaces, `]`, `{`) breaks or injects CSS. Also `injectPetStyles` caches by `petType`, so a re-downloaded pet with changed sprites serves stale CSS for the session.
- **Untracked timers not cleared in `destroy()`** — `src/renderer/pet.js:48, 89`: the `.clicked` (200ms) and `.transitioning` (100ms) timeouts aren't stored or cancelled in `destroy()` (all other timers are). Harmless in practice since the element is detached.
- **Store `readAll` ignores the `name` filter** — `src/tracking/stores/filesystem-store.js:75-81` vs `src/tracking/usage-tracker.js:31-39`: `UsageTracker.getEvents` supports `{type, name, since}`; the store's `_applyFilter` supports `{type, since, limit}` and silently drops `name`. A caller filtering persisted events by `name` gets unfiltered-by-name results.
- **`falling_asleep` for an unknown session creates-then-removes a pet** — `src/app/event-server.js:154` + `idle-state.js`: after an app restart mid-session, a `SessionEnd` for an unknown key creates an idle pet (resize up), then removes it (resize down) — a phantom pet flickers and the overlay resizes twice.

## Verified not bugs

Checked during the audit and deliberately **not** flagged — intentional behavior, to prevent future re-flagging:

- **Hook error-swallowing** (`process.stdout.write('{}')`, exit 0 everywhere) — intentional; the pet must never block Claude Code (CLAUDE.md).
- **`/clear` and `/resume` filtering in `on-session-end.js`** — intentional; those end the session in place and the pet survives (`docs/` + CLAUDE.md).
- **Awaken suppression in non-idle states** — intentional whitelist pattern; only `IdleState` overrides `onAwaken()`.
- **`SubagentStop` not registered; idle woken only on `agentId`-tagged `action_completed`** — intentional per `docs/background-subagents-investigation.md`.
- **`CLAUDE_PROJECT_DIR` over cwd for project keying** — intentional (subfolder-pet fix, `docs/subfolder-pet-investigation.md`).
- **Logger truncate-to-zero rotation** — deliberate simple rotation; write errors intentionally swallowed.
- **Mock mode not supporting sprite download** — documented limitation, not a bug.

## Unverified / worth a second look

- **Clock-skew on the offline grace period** — `src/app/license-manager.js:78-82`: `isWithinGracePeriod` uses wall-clock `Date.now() - validatedAt`; a deliberate clock rollback could extend offline access. No monotonic-time guard exists. Severity depends on the threat model.
- **Corrupt `license.json` lingers** — `src/app/license-manager.js`: on parse failure the in-memory state resets to defaults but the corrupt file is not rewritten or quarantined. Behaviorally acceptable (user re-activates); flagged as a design choice.
- **`filesystem-store` single-flight chain has no backpressure** — `src/tracking/stores/filesystem-store.js:44-55`: a pathological event storm would grow the pending-promise chain unbounded. Documented traffic is human-paced, so not realistically triggerable.
- **Hook stdin field names** — hooks key off `input.permission_mode`, `input.reason`, `input.stop_reason`, `input.agent_id`, etc. These match `docs/hook-table.md` but were not verified against a live Claude Code hook payload spec; a source-side field rename would silently misroute plan/working detection and subagent-wake.
